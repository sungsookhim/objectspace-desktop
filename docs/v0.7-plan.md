# Version 0.7: plan

2026-11-25, with [v0.6-design.md](v0.6-design.md) parts 6 to 9 (the drafts for 0.7) and the owner's choices of 2026-11-25 folded in: one desktop across all screens; all four looks for other programs (GTK 3, cursors, Qt, the icon theme); X11 programs scaled by themselves, on by default; libadwaita programs following the scheme through what libadwaita supports, the stylesheet over them dropped. The owner added a Screens object (step 5) on 2026-11-26. Each step is usable on its own, ends with its tests passing (`make check`, `gui-test`, `comp-test`, the visual and golden checks) and CI green, and is checked by the owner on the VM before the next.

For the screens, the VM needs a second monitor: VirtualBox, the machine's Settings, Display, **Monitor Count** 2 (the VM off), then in the guest Settings, Displays, the two arranged side by side.

## Steps

1. **Start** (S): VERSION 0.7.0-dev; the owner's choices folded into the design. **Done** (2026-11-25).
2. **More than one screen: the compositor** (L): the screens' arrangement and scale from GNOME's `monitors.xml` (positions, the primary); TheBar on the primary screen, the others' usable area all of them; windows opened on the screen with the pointer, maximized and tiled on their own, moved between screens by dragging and with Super+Shift+Left and Right; screens added and removed while running (windows on a removed one moved to the primary); open windows restored at login on the screen they were on, or the primary if it is gone; the lock screen on every screen. **Checks:** a headless test with two outputs: TheBar on the first, a window maximized on the second fills it, Super+Shift+Right moves it, the second removed: the window on the first. **Built** (2026-11-25, awaiting the owner's check): the screens placed and the primary chosen from GNOME's `monitors.xml` (followed when it changes); TheBar, notifications, the Launcher and the lock screen's panel on the primary (the lock's shade over all); new windows on the screen with the pointer; windows restored at login on the screen their title bar was on, else the primary; Super+Shift+Left and Right move the front window to the next screen (its place, maximized or fullscreen kept); a screen gone: its windows to the primary; OS/2's **Alt+F10** maximizes and restores. Tiling (Super+Left and Right) is not done (Objectspace has none yet). The desktop still on the primary alone (step 3). `tests/comp/screens.sh` (two headless screens; `OSD_COMP_HEADLESS=WxH,WxH`, script steps `plug`, `unplug`, `shot PATH SCREEN`). **Verified by the owner** (2026-11-25).
3. **One desktop across all screens** (M): the desktop window spans the screens' bounding box, each screen's part its own wallpaper (the picture per screen as set: scaled, centred and so on, for each screen); icons anywhere a screen shows (none in the gaps between screens of different sizes: a drop there lands on the nearest screen); Arrange and new icons fill the primary screen first; the Trash Can in the primary screen's corner; a screen removed: its icons moved onto the others (positions kept for when it comes back). **Checks:** a headless test with two outputs: the wallpaper on both, an icon dragged onto the second stays there after logging in again, the second removed: the icon on the first. **Built** (2026-11-25, awaiting the owner's check): the compositor sizes the desktop to the box round all screens' usable areas and tells it where each is (an `S` line, the primary first); the wallpaper (GNOME's or the desktop's own) fitted to each screen (GNOME's "spanned": one across them all); icons kept on a screen (a drop in a gap, or a screen gone: shown on the nearest, the stored place kept, so the icon is back when the screen is); Arrange and new icons fill the primary (the layout's origin at its corner); the Trash Can's corner and the desktop's message box on the primary. Inside GNOME nothing changes (the desktop on GNOME's primary, as before). `tests/comp/desktop-screens.sh` (drag onto the second, unplug, plug again). **Verified by the owner** (2026-11-25); fixed after: the file picker (a Background's picture, a sound) showed the widget set's old drawn folder for folders and files with no preview, now the icon theme's, as folder windows.
4. **Sharp X11 programs on scaled screens** (M): XWayland told to draw at the screen's scale (`Xft.dpi`, `GDK_SCALE`/`QT_SCALE_FACTOR` for programs started from the session; XWayland's own scaling when wlroots offers it), with the System setting **Scale X11 programs themselves** (on). **Checks:** a headless test at scale 2: an X11 test client's window drawn at twice its size in pixels, sharp (a one-pixel line stays one pixel at scale 2), off: as before. **Built** (2026-11-26, awaiting the owner's check): wlroots 0.20 has no scaling for XWayland, so as GNOME's xwayland-native-scaling and other compositors do it: X11 programs live in device pixels at one scale (the largest screen's); XWayland is told the screens' places and sizes times it (an xdg-output of the compositor's own, shown to XWayland alone), X11 windows' places, sizes and pointer positions multiplied and divided on the way, their pictures shown at 1/scale (not stretched); `Xft.dpi` (96 times the scale, through `xrdb` when installed) for their fonts, and `GDK_SCALE` for the programs the desktop starts when every screen has the same whole scale (GTK 3, Java, Chromium). The System's Window page: **Scale X11 programs themselves (sharp on scaled screens)**, on. Fractional scales: windows sharp, toolkits that only take whole scales (GTK 3's widgets) drawn smaller than the rest, their text the right size. `tests/comp/x11-scale.sh` (scale 2: the root in pixels, a window 1:1, a click in its middle; off: as before).
5. **A Screens object** (M; the owner's, 2026-11-26: GNOME's Settings, Displays needs Mutter's own interface and cannot change screens in the Objectspace session): in System Setup, a notebook with a page per screen (resolution and refresh from its modes, scale, place beside the others, primary, on or off) and a picture of the arrangement to drag the screens in; saved to GNOME's `monitors.xml` (the current configuration), so GNOME and Objectspace keep one setup; the compositor applies it at once (it follows `monitors.xml` already), with OS/2's way of asking to keep a change (back after 15 seconds unless kept). Inside GNOME it opens GNOME's Settings, Displays. **Checks:** headless, two screens: a scale and a place changed in the notebook: `monitors.xml` written, the compositor's screens as set; a mode not kept: back after the time. **Built** (2026-11-26, awaiting the owner's check): the Screens object in System Setup (its icon, two monitors, a draft for the owner's approval); its notebook: **Arrangement** (a picture of the screens: one dragged lands beside the nearest, edges near each other's aligned; the primary chosen) and a page per screen (Monitor, On, Resolution, Refresh rate, Scale); each change written to `monitors.xml` at once (the configuration for the screens connected now first, GNOME's others for other sets of screens kept, GNOME's own vendor, product and serial for a screen kept); a mode, a scale or a screen on or off asked to be kept: **Keep** or **Go back**, back by itself after 15 seconds; the last screen on cannot be turned off. The compositor now takes from `monitors.xml` the configuration for the screens connected (else the first naming one), and a screen's mode (resolution, refresh) and off as well as its scale, place and primary, and tells the desktop each screen's modes (the `M` lines). Inside GNOME (no compositor of ours) it starts GNOME's Settings, Displays. `tests/comp/screens-object.sh` (two headless screens: dragged below, a resolution not kept, a scale kept, off and on again, GNOME's names and configurations kept); `tests/comp/x11-scale.sh` added to `comp-test` (it was left out at step 4).
6. **libadwaita programs follow the scheme** (S): a dark scheme sets GNOME's `color-scheme`, the nearest of GNOME's accent colours, high contrast, the System's fonts and text scale; written in the Objectspace session at login and on a change, inside GNOME only on a change made in Objectspace. **Checks:** a test with a private gsettings backend: Dark chosen: `prefer-dark` and the nearest accent; Classic: `default`; High contrast: high contrast on; a font changed: GNOME's font. **Built** (2026-11-27, awaiting the owner's check): a scheme is dark by its windows' background (a scheme of the user's made from Dark is dark too), high contrast by its name; GNOME's `accent-color` the nearest (by hue; slate for a grey) to the scheme's selection colour (Classic's navy: blue); in the Objectspace session Objectspace's scheme is written to GNOME at login (inside GNOME, GNOME's values still win at start, and the accent is written only for a scheme chosen in Objectspace); from GNOME, the scheme changes only when it is not already as GNOME says (a dark scheme of the user's stays when GNOME says dark). Fonts and text size: Objectspace's interface font and text scale are GNOME's (followed since 0.2), so libadwaita programs have the same already; nothing more is written (the scheme's Dialogs font has no libadwaita setting). `tests/comp/libadwaita.sh` (a private keyfile backend: login, Dark, High contrast, Classic, GNOME's dark; inside GNOME).
7. **A GTK 3 theme from the scheme** (M): `~/.local/share/themes/Objectspace-<scheme>/gtk-3.0/gtk.css` made from the scheme (window, buttons, selection, text, fonts, OS/2-like bevels), set for the session's GTK 3 programs only, made again when the scheme changes. **Checks:** the theme file for each scheme (the colours in it); a GTK 3 test program drawn in the session with the scheme's colours (a screenshot's pixels).
8. **An Objectspace cursor theme** (M): OS/2's arrow, busy clock, hand, text, resize and move cursors redrawn in the icon set's style by `tools/icons` (the owner approves the drawings, as for the icons), at 24, 32, 48 and 64; installed with the RPM; the session's and the compositor's cursor (a System setting: Objectspace's or the system's). **Checks:** the theme's files (every cursor name programs ask for, each size); the compositor's cursor from the theme in a headless screenshot.
9. **Qt programs and the icon theme** (M): the scheme's colours as a Qt palette (`qt6ct`/`qt5ct` colour schemes, used when those are installed); Objectspace's isometric icons exported as a freedesktop.org icon theme (folders, file types, places) so other programs' file dialogs show the same pictures, chosen for the session. **Checks:** the palette files for each scheme; the icon theme's `index.theme` and every name it maps; a GTK file dialog's folder icon from it (a screenshot).
10. **The release, 0.7.0** (S): the release notes; the RPMs in mock; the owner's install on a clean VM; the GitHub release.

## Order and risks

- **The screens first:** the largest change, touching most of the compositor (placement, TheBar, the desktop, restoring windows); the headless backend can make several outputs, so it is tested without a second monitor, then on the VM with two.
- **The desktop across screens** changes the desktop folder's positions: kept in each icon's place as now, in the spanning area's coordinates, so one screen again finds them where they were.
- **The looks** (5 to 8) write files and settings other programs read: only the session's own (`~/.local/share/themes`, the session's GTK settings, qt6ct's), never GNOME's theme inside GNOME; libadwaita's settings are GNOME's own and written only as step 5 says.
- **The cursors** are new drawings: the owner's approval of the set before it is wired in, as with the icons.
