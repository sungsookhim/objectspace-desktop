# Version 0.8: design

Draft, 2026-11-28, with the owner's choices of the same day folded in (**Decided** below). 0.8 gathers what the roadmap put after 0.7 ([roadmap.md](roadmap.md), "Proposed order", 0.8: network and jobs): the service and the object core, and one of the owner's waiting to-dos. The rest is proposed and can change with the owner's review.

Seven parts, in three groups:

| Group | Parts | Size |
|---|---|---|
| **A. Network** | 1. the Network object and network shares; 2. connecting to a share | M, M |
| **B. Jobs and objects** | 3. undo for jobs; 4. disk full and quota; 5. central objects tidied | M, S, M |
| **C. Finding and kinds** | 6. Find in titles, classes and settings, with an index; 7. file types from `user.mime_type` and the Type page | M, S |
| **D. The owner's to-do** | 8. Objectspace Terminal's own settings | S |

**Decided** (the owner's, 2026-11-28):

- **Network:** the shares already mounted, and connecting to a share by its address, remembered as an object; no discovery of computers on the network (unreliable on many networks; perhaps later).
- **RDP:** deferred past 0.8 (GNOME's own RDP needs Mutter's interfaces, which Objectspace's compositor has not; a project of its own).
- **Undo:** a history, the last 20 jobs, kept across logins.
- **Objectspace Terminal's settings** come into 0.8; the design updates (window borders, title-bar buttons, the selection rectangle, TheBar's layout) wait for another slot.

## 1. The Network object and network shares (0.8)

**My System** gets **Network** (OS/2 had a Network folder in its System): a folder of the network shares mounted now, each a share object, as Drives shows the disks.

- **What counts as a share:** a mount of NFS (`nfs`, `nfs4`), SMB (`cifs`, `smb3`), or one made by GNOME's virtual file systems (`gvfsd-fuse`'s folders under `/run/user/UID/gvfs`: SMB, SFTP, WebDAV, FTP, as GNOME's Files mounts them). Read from `/proc/self/mountinfo`, followed when it changes (as Drives follows udisks).
- **A share object:** its title is the share's name and server (`projects on fileserver`), its icon a network drive's (drawn for the owner's approval, with the other new icons); opening it opens the share's folder; its menu has **Disconnect** (unmount: `umount` for the system's own mounts needs the system's permission and is offered only where the user may; GNOME's through `gio mount -u`).
- **Objects on a share keep their state** (titles, icons, positions, settings). Where the share takes extended attributes (NFS 4.2 does; SMB through `cifs` usually not; GNOME's FUSE mounts never), they travel with the files as everywhere; where it does not, they are kept in Objectspace's database by the **share's identity** and the path inside it: `nfs://server/export` or `smb://server/share`, not the place it is mounted at nor a device number, so the state comes back when the share is mounted again elsewhere, by another program, or after a reboot.
- **Changes made by others are seen:** the kernel does not report changes made on the server or by another computer, so a folder window open on a share lists the folder again every five seconds (only what changed is redrawn), and the folder is read again when its window is opened. Jobs onto a share work as onto a disk (moves across file systems are copies).
- **Slow or gone servers do not hold the desktop up:** every look at a share (listing, attributes, free space) is done off the service's loop, with a time limit; a share that does not answer shows as unavailable (its icon greyed) and its windows say so, rather than freezing.

## 2. Connecting to a share (0.8)

The Network folder's menu (and its **Connect to a share...** object, first in it): an address, `smb://server/share`, `nfs://server/export`, or any GNOME's virtual file systems take (`sftp://`, `dav://`, `ftp://`). Objectspace mounts it through GIO (`gio mount`, GNOME's virtual file systems, installed with GNOME): no system password needed, as GNOME's Files does.

- **A password:** asked in Objectspace's dialog (user, domain for SMB, password, **Remember the password**: kept in GNOME's keyring, as GNOME's Files keeps it, so either can open it again without asking).
- **Remembered:** each share connected to is kept in the Network folder as a connection object (its address, its title), shown even when not mounted (greyed); opening it connects again first. Its menu: **Disconnect**, **Forget** (removes the connection and its remembered password).
- **Errors** say what happened in words (the server not found, the share not there, the password refused, not allowed) in the folder's status line and a message.

## 3. Undo for jobs (0.8)

**Edit > Undo** (**Ctrl+Z**) in folder windows and on the desktop undoes the last job the user did, anywhere; again, the one before, up to the last 20, kept across logins (in the jobs' journal). The menu item says what it undoes: "Undo move of 3 objects to Projects".

- **What a job's undo is:** a move: the objects back where they were, under their old names; a copy: the copies into the Trash Can; put in the Trash Can: put back; a rename: the old name back; made from a template: into the Trash Can; a shadow made: the shadow deleted. Deleting for good (emptying the Trash Can, **Delete** with Shift) is not undone: it says so before it is done, as now.
- **Things changed since** (an object moved again, renamed, deleted) are left and named in the report; the rest is undone. An undo is a job itself, with its progress, name clashes and errors as any job (and not undone in its turn: there is no redo in 0.8).

## 4. Disk full and quota (0.8)

A job that runs out of room (`ENOSPC`) or over the user's quota (`EDQUOT`) pauses rather than failing: the half-written item is removed, and the job asks: **Retry** (after making room), **Skip** this item, or **Cancel**; what was done stays done. Before a copy to another file system starts, its size is checked against the free space there, and if it will not fit the user is told first (copy anyway, or cancel).

## 5. Central objects tidied (0.8)

Objects with no file of their own (a shadow on the desktop, a program object, a connection) are kept centrally, in the database ([object-core-design.md](object-core-design.md)). 0.8 closes three gaps:

- **Deduplication:** an object that exists both centrally and as a local `.osdobj` file (after a restore, or a folder that started keeping files) is kept once; the local file wins, as the extended attribute wins over the database.
- **Cleanup:** central objects whose folder was deleted outside Objectspace are removed at the next scan, with their state, rather than staying forever in the database.
- **Becoming files:** a central object moved into a folder that keeps objects as files (**Keep objects as files here**, the folder's View page) becomes an `.osdobj` file there, and back when moved out.

## 6. Find in titles, classes and settings, with an index (0.8)

Find (the Find object, TheBar's button) searches more than names:

- **Titles:** an object's own title (a program's, a shadow's, one renamed in Objectspace) as well as its file's name.
- **Kinds:** objects of a class (all programs, all shadows, all folders kept as Work Areas), from the class's list as the Find window offers it.
- **Settings:** objects with a setting (a property's name and a value: every folder in the Details view, every object with an icon of its own).
- **An index:** what Objectspace knows of its objects is in its database already; names are not. A name index of the home folder (and of drives the user chooses), built in the background at low priority and kept up to date from the watch helper's reports, makes a search of the home folder instant rather than a walk. **Index files for Find** (System, a new Find page; on for the home folder) chooses where; without an index Find walks the folders as now. The index is the user's own (in the database), never shared.

## 7. File types from `user.mime_type`, and the Type page (0.8)

As OS/2's `.TYPE` extended attribute: a file's type can be set on the file itself, and Objectspace honours it before its name and its contents.

- **Read:** a file's `user.mime_type` attribute (freedesktop.org's own name for it, which other programs set too) is its type: its icon, the programs it opens with, its class's settings.
- **The Type page** of a data file's notebook: its type now (and where it comes from: its name, its contents, set on it), a list of types to choose from (shared-mime-info's, the common ones first, or typed), and **Default** to take the set one off. Set on the file where it takes attributes, else kept in the database as other state is.

## 8. Objectspace Terminal's own settings (0.8; the owner's, 2026-11-27)

A **Terminal** settings object in System Setup (as Mouse and Sound), its pages: **Colours** (background and text, the Colour Palette's samples dropped on them; and the 16 colours programs use, defaulting to the scheme's), **Font** (family and size; the Font Palette's samples dropped on it; the System's terminal font moves here), **Window** (columns and rows at start), **Scrollback** (how many lines are kept, 0 to 100 000). Open terminals follow a change at once, except the window's size.

## Order and risks

- **Network first** (parts 1 and 2): the largest unknowns (servers that do not answer, shares without attributes, identity across mounts), tested headless against a local NFS export and Samba share where the machine allows, else a FUSE mount standing in for a share.
- **Undo** builds on the jobs' journal, which already keeps each job; its risk is in the details (names changed since, clashes on the way back).
- **The index** must stay out of the way: built at low priority, a size limit, and Find working without it.
- **New icons** (a network share, a connection, Connect to a share, the Terminal object) are drawings for the owner's approval before they are wired in.

## Tests

Each part with its headless test as before (the service's `make check` for the core, `comp-test` for what is seen): a share's state kept across a remount at another place; an open window seeing a file made behind its back; a connection's password asked and refused; each kind of job undone, and one whose objects changed since; a copy into a full file system (a small loop-mounted or tmpfs one); central objects deduplicated, cleaned up, made files; Find by title, class and setting, and from the index; a type set and honoured; the Terminal's settings in a running terminal.
