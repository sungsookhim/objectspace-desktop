# Version 0.8: plan

2026-11-28, with [v0.8-design.md](v0.8-design.md) and the owner's choices of 2026-11-28 folded in: the shares mounted and connecting to a share by address, no network discovery; RDP deferred; undo with a history of 20; Objectspace Terminal's settings in 0.8. Each step is usable on its own, ends with its tests passing (`make check`, `gui-test`, `comp-test`, `install-check`, the visual and golden checks) and CI green, and is checked by the owner on the VM before the next.

## Steps

1. **Start** (S): VERSION 0.8.0-dev; the design and this plan; the owner's choices folded in. **Done** (2026-11-28).
2. **File types from `user.mime_type`, and the Type page** (S): the attribute read before the name and the contents; a data file's Type page (its type and where it comes from, a list to choose from, Default). **Checks:** a file with `user.mime_type` set shows that type's icon and opens with its program; set from the Type page: the attribute written (or the database, on a file system without attributes); Default: back to the name's type. **Built** (2026-11-28, awaiting the owner's check): `osd_file_mime` (classes/OsdDataFile.c) reads `user.mime_type` first (a valid type's name; on a file system without attributes, a database row by the volume and the path), then the name, then the contents; used for a file's class, the programs it opens with, Open's cascade and the data file's own type; the listing's details carry a type set on a file, and its icon is that type's. A data file's **Type** page: **Its type** (and where it comes from: set on it, its name, its contents) and **Set its type** (by its name and contents, the one set, the name's and contents', then the common types); set: `user.mime_type` written (the database where the file system takes no attributes), taken off by choosing "by its name and contents". `tests/openwith` (set on a file: Open's programs and a double-click; the Type page shown, set, taken off). The database for a file system without attributes is not tested headless (no FAT drive without root): on the VM, a FAT USB stick.
3. **Network shares** (M): the Network folder in My System; the mounted NFS, SMB and GNOME virtual-file-system shares as share objects (title, icon, Disconnect); state on shares without attributes kept by the share's identity and path; open folder windows on a share listed again every five seconds; a share that does not answer shown as unavailable, never holding up the service. **Checks:** headless, a FUSE (or local NFS/Samba) share: listed, opened; a title set on a file there kept when the share is mounted again at another place; a file made behind a window's back shown within five seconds; a share stopped answering: unavailable, the service still answering. **Built** (2026-11-28, awaiting the owner's check; the icons approved the same day): network shares are volumes known by their address (`net:smb://server/share`, `net:nfs://server/export`, `net:sftp://user@host/path`; the kernel's NFS, SMB and SSHFS mounts, and each of GNOME's virtual file systems' folders in `/run/user/UID/gvfs`), so the state of the objects on one (kept in the database where it takes no attributes) comes back wherever it is mounted again; **Network** in My Storages (first start step 14; Restore Desktop too): a share object (OsdShare, a kind of drive) for each share mounted, titled "share on server", its icon lit while connected, its notebook's Share page its address and the Drive page's details; opening it opens its folder; **Disconnect** (GNOME's: `gio mount -u`; the kernel's: `umount`, the user's own mounts); a share gone is parked (its title and settings kept) and comes back when it does; every five seconds GNOME's shares are looked for (they do not show in mountinfo) and folder windows open on a share are listed again, what came or went told to them. Listings now show titles and icons kept in the database for files on a file system without attributes (a FAT drive's too, which did not). Two races found and fixed on the way: a share object in memory saving its folder back after it was parked (now dropped from memory first, then moved), and a share gone while a volume scan ran not noticed (GNOME's shares are now compared with the volumes known, not with the last look). `tests/network` (in `make check`). Not done: a share that does not answer shown as unavailable (a slow server can still hold a worker; for step 4 or later).
4. **Connecting to a share** (M): Connect to a share... (an address; `gio mount`), the password dialog (Remember: GNOME's keyring), connections kept as objects (open: connect; Disconnect, Forget), errors in words. **Checks:** a local SFTP or WebDAV server where available (else `gio` stood in for by a test double): connected, remembered, a wrong password refused in words, forgotten. **Built** (2026-11-28, awaiting the owner's check): **Connect to a share** in Network (first start step 15; icon `net-connect`): opening it asks for an address (`server/share` taken as a Windows share); osdd runs `gio mount ADDRESS`, answering its questions (user, domain, password) as they come; none given and one asked for: "password needed", and the desktop asks for a user name (DOMAIN\\user for a domain) and the password (**Connect**, **Connect and remember**: stored with `secret-tool` under the attributes GNOME's Files looks up, so gvfs finds it and neither asks again); refused, the server not found, no such share, not supported: said in words. The share's folder opens; its share object is remembered (its address with its user): shown in Network when not connected (its icon dark), opening it connects again first (the keyring's password; else asked), its menu **Connect**/**Disconnect** and **Forget** (the object and its password gone). The RPM recommends gvfs-fuse, gvfs-smb and libsecret. `tests/network` (a gio and secret-tool of the test's own: no password, needed, wrong, right and remembered, disconnected and opened again from the keyring, forgotten).
5. **Undo for jobs** (M): Edit > Undo and Ctrl+Z; a history of 20 in the journal, kept across logins; the undo of each kind of job; objects changed since left and named. **Checks:** a move, a copy, Trash, a rename, from a template, each undone; two undone in turn; one whose object was moved since: the rest undone, that one named; after a restart, still there.
6. **Disk full and quota** (S): a job pausing on `ENOSPC` and `EDQUOT` with Retry, Skip, Cancel, the half-written item removed; a copy's size checked against the free space first. **Checks:** a copy into a small tmpfs: told before; copied anyway: paused when full, Skip, Retry after room is made.
7. **Central objects tidied** (M): deduplication against `.osdobj` files; cleanup of central objects whose folder is gone; a central object becoming an `.osdobj` file in a folder that keeps files, and back. **Checks:** each in the service's tests.
8. **Find in titles, classes and settings, with an index** (M): the Find window's Title, Kind and Setting; the name index of the home folder (and chosen drives) built at low priority and kept up to date; the System's Find page. **Checks:** found by title, by class, by setting; a file made after the index was built found from it; Find working with the index off.
9. **Objectspace Terminal's own settings** (S): the Terminal object in System Setup: colours (and the 16), font and size, columns and rows, scrollback; open terminals follow. **Checks:** a terminal's colours and font changed while open (a screenshot's pixels); the scrollback's length; a new terminal's size.
10. **The release, 0.8.0** (S): the release notes; the RPMs in mock (x86_64) and on GitHub's ARM machines (aarch64, experimental); the owner's install; the GitHub release.

New icons (a network share, a connection, Connect to a share, Network, the Terminal object) are drawn for the owner's approval in the step that first needs them.

## Order and risks

- **File types first** (step 2): small, and the Type page is a pattern the others reuse.
- **The network** (steps 3 and 4) carries the most risk: servers that do not answer, shares without attributes, identity across mounts. Tested headless with what the machine and CI allow (a FUSE file system always; NFS and Samba where they can run), on the VM against a real share.
- **Undo** (step 5) rests on the journal; its risk is in objects changed since.
- **The index** (step 8) must stay out of the way: low priority, a size limit, Find unchanged without it.
