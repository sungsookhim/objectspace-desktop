# Version 0.3 design: daily use and OS/2 fidelity

Draft v0.1, 2026-11-21. The objectives are the roadmap's "0.3 Daily use and OS/2 fidelity" ([roadmap.md](roadmap.md), "Proposed order"), with the owner's two ideas after 0.2 (the desktop's background page; System Setup on the desktop menu). This document says how each is built on 0.2. The implementation plan is [v0.3-plan.md](v0.3-plan.md).

The roadmap's open choices (**?**) are settled here with a proposal, marked **Proposed**; the owner's answers turn them into **Decided** before their step is built.

## 1. Principles for 0.3

- **As OS/2 had it, where Linux allows.** Each item follows Warp 4's behaviour and names (menus, notebook pages, settings) unless the roadmap says otherwise.
- **Settings are data.** New notebook pages use the page/field description classes already return (`wpAddSettingsPages`: `page`, `field` lines with `text`, `checkbox`, `number`, `choice`, `icon`, `info`). Two field kinds are added: **`file`** (a path with a Browse... button and, for pictures, a preview) and **`color`**. Every later page uses them.
- **wpsd owns shared state.** Sorting of big folders, filters, sort orders and work-area groups live in wpsd, so every window on a folder (and Find, and the WarpCenter) sees the same thing.
- **Both modes.** Every item works inside GNOME and in the WPS session, except where marked (work areas' window control).
- **Upgrades keep what users have.** New settings start at today's behaviour; first-start steps (version 9 onwards) add, never rebuild.

## 2. The desktop's menu: Lockup, Shut down, System Setup

OS/2's desktop menu had, after the folder's items: **System setup**, **Lockup now**, **Shut down...**, and the window list. 0.3's desktop menu (the background's, `got_menu` in `wps-shell.c`, `f->desktop`):

| Item | Does |
|---|---|
| Open, Open parent, Refresh, Find..., Sort, Arrange, Paste | as today (folder items) |
| **System setup** ▸ | a cascade: the System Setup folder's objects (System, Sound, Mouse, Scheme Palette, Font Palette, WarpCenter, LaunchPad...), each opening its notebook; read from the folder when the menu opens, so objects the user adds there appear |
| **Lockup now** | the session's lock: the compositor's lock screen in the WPS session, `org.gnome.ScreenSaver.Lock` inside GNOME (the WarpCenter's Lockup today) |
| **Shut down...** | the WarpCenter's dialog (Shut down, Restart, Log off), shared code |
| Window list, Minimized windows | as today |

- **Shared code:** the WarpCenter's end-session dialog and lock call move into one place (`gui/shell/session.c`), used by the WarpCenter, the desktop menu and the LaunchPad.
- **Proposed:** the items appear in both modes; inside GNOME, Shut down goes through `org.gnome.SessionManager` (GNOME's own dialog), as the LaunchPad does now.

## 3. Backgrounds: the desktop's and folders'

OS/2 gave every folder (the desktop included) a **Background** page: a colour, or an image (normal, tiled, scaled) from a list or a file. Today the desktop follows GNOME's background (`wallpaper.c`, `org.gnome.desktop.background`) and folders have none.

- **The Background page** (WPFolder, so the desktop and every folder have it):
  - **Image:** None, or a file (`file` field, pictures only, preview); **Display:** Normal (centred), Tiled, Scaled (to fill, kept in proportion), Stretched.
  - **Colour:** a `color` field (behind the image, or alone).
  - **Desktop only:** **Use GNOME's background** (checkbox, on by default). On: as today, following GNOME's settings live. Off: the page's own image and colour.
- **Stored** on the folder object (its state, so it travels with the folder like its icon positions); pictures decoded through glycin as now (`wallpaper.c`'s decoder generalised: one decode cache keyed by path and size).
- **Folder windows** draw their background under the icons (scrolled with them for Tiled, fixed for the others).
- **Proposed:** the desktop page does not write GNOME's setting: WPS's choice is WPS's alone, and GNOME's own desktop and lock screen keep theirs. (Alternative: write GNOME's `picture-uri` too, so both agree.)

## 4. Details view: sorting and columns

Today the details view lists rows in directory order, paged from wpsd (`service/listing.c`); the icon view's Sort arranges icons in the window (`sort_icons`).

- **Sorting in wpsd** (rows are paged and shared, roadmap): `list` takes a sort key and direction (`name`, `type`, `size`, `date`, `created`, `class`), and wpsd answers pages in that order.
  - Name and type sorts need no details; size and dates need a stat of every entry, done on a worker after the folder is read, in chunks (a million-entry folder: seconds, with "Sorting..." in the status line; the rows show in directory order until then).
  - **Folders first** in every sort (the roadmap's "sort by size" item), as OS/2's details view did.
  - The sorted order is a per-folder index, rebuilt when the listing changes (an insert or remove patches it; a big batch rebuilds it).
- **Clicking a column heading** sorts by it; again reverses it; an arrow shows which.
- **Kept per folder** (**Proposed**, OS/2's "Always maintain sort order"): the folder's Sort page holds the sort key, direction and **Always maintain sort order** (checkbox). The details view always shows the folder's order; the icon view re-sorts new icons into place only when Always maintain is on. Today's `sort_order` field becomes this.
- **Columns** (**Proposed**, today's plus Type and OS/2's): Icon, Title, Real name, Type, Size, Last write, Last access, Created, Class. Shown by default: Icon, Title, Real name, Type, Size, Last write.
  - Chosen on the folder's **Details view** page (checkboxes; order fixed), with the System object's choice as the default for folders that have none.
  - Column widths dragged at the heading, kept per folder.

## 5. Icon view: OS/2's layout, locked positions

- **OS/2's layout** (roadmap "D"): every title shown whole (wrapped at the icon cell's width), each row as tall as its tallest title, Arrange spacing to suit. Today: two lines, the whole title when selected.
  - The flowed layout (`layout.c`) computes rows of icons, each row's height from its tallest title; hand-placed icons keep their positions, and Arrange flows them.
  - A setting on the folder's **Icon view** page: **Titles:** whole (OS/2) or two lines (today's); default whole for new folders and the desktop.
- **Lock position** (owner's to-do): **Lock position** on an object's menu (a check item) and on its **General** page; and **Lock positions of all icons** on the folder's Icon view page.
  - A locked icon cannot be moved within its folder: a drag that would only reposition it does nothing.
  - **Proposed:** it can still be dragged onto other objects and to other folders (move, copy, shadow), as OS/2's did: the lock is about its spot, not the object.
  - Arrange and Sort leave locked icons where they are and flow the others around them.
  - Stored with the icon position (the folder's position record gains a flag).

## 6. The folder search field; hidden files

- **The search field:** a field at the top of folder windows (Ctrl+F puts the cursor there; the Find window stays on the menu and on Ctrl+Shift+F). Typing filters the view to names and titles that contain the text, live; Esc clears it.
  - **The filter is wpsd's:** `list` takes a filter, and wpsd pages only the matching entries (a million-entry folder stays paged). Each window has its own filter.
  - In icon view, filtered icons are drawn flowed (positions are not used while filtering).
- **Hidden files** (roadmap **?**):
  - **Lock files** (`.~lock.*#`, `.*.swp`, `.#*`, `~$*`) are never listed: they are already recognised (`wps_is_lock_file`) and shown as the in-use emphasis on the file they lock.
  - **Proposed:** names starting with a dot are hidden by default (today they are listed), with **Show hidden files** on the folder's **Include** page (OS/2's page for filters) and a default in the System object. One rule for every folder, the upgraded ones included: `.cache` and `.config` are rarely wanted on view, and the setting brings them back.

## 7. Open With

Today data files have "Open With" on their menu but it does nothing (a G2 placeholder), and types without a default program go to `xdg-open`.

- **The Open cascade** of a data file, as OS/2's: the default program first (bold), then the other programs that take the file's type (from the desktop entries' `MimeType`, and `mimeapps.list`'s added associations), then **Other program...**. Today's flat Open item becomes the cascade's first entry, so a double-click is unchanged.
- **Other program...** opens a picker: the Programs folder's programs, with **Always use for this type** (writes `mimeapps.list`'s default, shared with GNOME).
- **Not in 0.3:** per-file associations (OS/2's data-file Menu page); associations come from the type, and programs' Association page (section 8).
- **Programs launched through Open With** are tracked like any open (in-use emphasis, Work Areas), not handed to `xdg-open`.

## 8. Program settings: type, close on exit, terminal

The Program page (WPProgram, `wpAddSettingsPages`) gains:

- **Program type** (choice): Automatic (today's guess: a binary without a window library, or a script, runs in a terminal), Window, Text mode (in a terminal).
- **Close window on exit** (checkbox, text mode only; on by default): off keeps the terminal open after the program ends (the terminal's "hold" option, or `; read` for terminals without one).
- **Working directory** (text; OS/2's page had it): empty means the program's folder or home.
- **The terminal to use:** a **Terminal** choice in the System object (Automatic: the first installed of today's list; or one of them; or a command line), replacing `WPS_TERMINAL` (still read if set).
- **Association** page (OS/2's): the types the program opens, from its desktop entry, shown; editing writes a user copy of the desktop entry (`~/.local/share/applications`), so GNOME sees it too.
- Stored in the program object; for programs from desktop entries, the type and close setting go in WPS's state, not the entry.

## 9. Templates: the New cascade, moving templates, Create another

- **New** ▸ on every folder's background menu (and the desktop's): the Templates folder's templates, each making an object here at the click's spot. Read when the menu opens.
- **Create another** ▸ on an object's menu asks for a **name and folder** (OS/2's dialog: a title field and a folder tree), instead of making "Copy of" in the same folder.
- **Moving a template by dragging:** today every drag of a template makes a new object. As in OS/2, a plain drag **makes** a new object; **Shift+drag moves** the template itself (and the Templates folder accepts drops of templates to reorder). The Template checkbox on the General page turns templates on and off, as now.
- **New data files' titles** no longer include the extension ("Text file", not "Text file.txt"); the file name still gets it.

## 10. Font Palette and the Sound object's picker

- **Font Palette** (OS/2's): a settings object in System Setup, a window of font samples ("12.Helvetica" style names: size and family).
  - **Edit font...** changes a sample (family, size, style from fontconfig).
  - **Drag a font onto** a WPS window: the folder's icon title font (that folder only), the desktop, the WarpCenter, a menu (all menus); onto a title bar: all title bars. Dropping with Shift sets it for every folder.
  - The fonts are WPS's own; with none set, WPS follows GNOME's interface font as now.
- **The Sound object** (WPSound): events become a list (event, sound) with a **Sound file** field (`file`, sounds only), **Play** and **None**; the sound theme's names shown as titles. Today each event is a text field.

## 11. The LaunchPad on the WarpCenter's footing

The roadmap: the LaunchPad updated to share features with the WarpCenter (its parts, settings and code), with tooltips.

- **Shared parts:** the LaunchPad's buttons and drawers use the WarpCenter's object menus (icons, cascades) and its system buttons (Lockup, Find, Shut down, Window list) come from the shared session code (section 2).
- **Tooltips** on the LaunchPad's buttons (the object's title) and on the WarpCenter's parts (the clock's date, a tray icon's tooltip, a meter's value).
- **Settings:** the LaunchPad's notebook gains OS/2's options: orientation (horizontal or vertical), small icons, text on buttons, float on top, close drawer after open.
- **Drawers followed:** a drawer listens to its folder's changes instead of reading it once when opened.
- **A keyboard shortcut:** the WarpCenter's menu on Ctrl+Esc's partner (proposed: Super opens the WPS menu in the WPS session; inside GNOME, Super stays GNOME's).

## 12. Work Area folders

OS/2's Work Area: a folder whose programs and windows are one group. Roadmap, 0.3 (added 2026-11-21), size M–L.

- **Setting:** **Work area** checkbox on the folder's File page (OS/2 put it there).
- **The group:** objects opened from a work area folder (by double-click, Open, or from a shadow in it) are its group; wpsd already records which object a program was started from (in-use emphasis), so wpsd records the work area too.
- **Opening the folder** opens its group's objects that were open when it closed; **minimizing** it minimizes their windows; **closing** it closes them (programs asked to close, as at logout); **restoring** it restores them.
- **At logout** the group's state is kept; at login a work area that was open reopens with its programs (they restart in the folder).
- **Window control:** the compositor links a program's process (its scope, `app-wps-*.scope`) to its windows, and takes minimize/close/restore commands for a group. **WPS session only** for minimize and restore; inside GNOME the extension does the same through Mutter (proposed as the step's second part).

## 13. Small items carried from 0.2

- At a new user's first start the desktop can briefly show an extra icon before it settles: find it with a headless first start, fix it.
- **Manual pages** for `wpsctl`, `wps-shell`, `wps-session`, installed by the RPM.
- **Confirmations** read from the System object, not `system.conf`.
- **Delete in tree view** acts on the whole selection.

## 14. Tests

- **Unit:** sorted listings (each key, folders first, reverse, inserts and removes patching the index, a 100 000-entry folder within a time bound); filters; Open With lists; program type and terminal choice.
- **Headless GUI** (`tests/comp/run.sh` scripts, `tests/gui/selftest.sh`): the desktop menu's cascade and Lockup; a Background page change drawn; heading clicks; locked icons not moving; the search field; the New cascade; a Font Palette drop.
- **Work areas:** a scenario with two programs opened from a work area, minimized, closed and reopened with the folder (headless compositor).
- **(VM):** the owner's check at each step, as in 0.2.

## 15. What 0.3 does not do

- Other programs' look (GTK, Qt themes) and GTK 4 frames: 0.4.
- RDP, more than one monitor, the Network object: 0.5.
- COPR: when a release needs `dnf upgrade` to find it.
- Undo for jobs.
