## 1. Principles for 0.4

- **As OS/2 had it, where Linux allows** (as in 0.3): Warp 4's names and behaviour unless said otherwise.
- **Icons are data.** An icon is a package (`.wpsicon`) or a picture; WPS's own icons come from a theme, never from code. The kinds' drawn pictures (`ui_draw_kind_icon`) stay only as the last fallback.
- **Settings are data;** new pages use the page/field lines (`file`, `color` included since 0.3).
- **wpsd owns shared state;** the window shows it.
- **Both modes,** inside GNOME and in the WPS session, unless a section says the WPS session only (window placement under Wayland is the compositor's).
- **Upgrades keep what users have.** New settings start at today's behaviour where they change what a user sees (the icon theme is the exception the owner chose: the new set is the default).

## 2. Icon packages and themes

**The package** (the owner's spec; the tool chain is built: `gui/shell/wpsicon.c`, `wpsctl icon pack|list|render`, `tools/icons/make_theme.py`, `make icons`):

- `NAME.wpsicon`: a zip of `SIZE.png` (square, any size) and optionally `icon.svg`; no manifest. The standard sizes 256 (master), 128, 96, 64, 32 are always in WPS's own; other sizes are used as exact matches. A plain picture is a package of one.
- **The size rules,** in device pixels: exact; the SVG (**librsvg**, new in 0.4: a build and run dependency, on every GNOME system); a whole multiple averaged down; the nearest larger scaled down; the nearest smaller scaled up (whole factors nearest-neighbour). Never a fractional nearest-neighbour scale.
- `.ico` and `.icns` are unpacked into packages when chosen on an Icon page (Choose...).

**Icon themes** (**Decided:** the flat variant is the default; themes are a System choice):

- A theme is a folder: `theme.ini` (`Name`, `Comment`, `Variant`) and `NAME.wpsicon` for each icon name. Installed: `/usr/share/wps/icon-themes/` (`wps-flat`, `wps-outline`, `classic`); the user's own: `~/.local/share/wps/icon-themes/`.
- **System object, Icons page: Icon theme** (a choice of the installed themes, by their `Name`). A change applies at once to every window.
- **Names** (the isometric set's): the kinds (`folder`, `program`, `program-text`, `object`, `link-mark`), data files by type (`file-text`, `file-image`, ... `file-data` for the rest), the special folders (`templates`, `startup`, `home`, `drives`, `programs`), the settings objects (`system`, `mouse`, `sound`, `scheme-palette`, `launchpad`, `warpcenter`, `messages`, `restore-desktop`, `minwin-viewer`), WPS's own (`computer`, `trash-empty`, `trash-full`, `drive-*`, `drive-missing`), the system buttons (`sys-lockup`, `sys-find`, `sys-shutdown`, `sys-windows`, `sys-logoff`).
- **How an icon is found:** an object's own icon (its Icon page) first, as now; else wpsd says which theme name the object shows (**Proposed:** `icon` in listings becomes `theme:NAME` for WPS's own objects instead of a PNG path, and data files get `theme:file-...` from their MIME type's family); the window looks it up in the current theme, then in `wps-flat`, then the drawn kind.
- **A missing name** in a user's theme falls back to WPS (flat) for that icon.
- **Data file types:** the MIME type's family picks the name: `text/*` text (code types: `file-code`), images, audio, video, fonts, archives (`application/zip` ...), documents, spreadsheets, presentations (the OpenDocument and OOXML types), disc images, packages (rpm, deb, flatpak), scripts (shell, Python); the rest `file-data`.

## 3. Icon sizes and the open icon

- **Icon size** (the owner's, 2026-11-22), **System, Icons page:** as OS/2's normal and large icons (32 and 40, with their mini icons), a choice of two **sets**, each a large, a middle and a small size:

  | Set | Icon views, desktop | LaunchPad, folder trees | Menus, Details view, title bars |
  |---|---|---|---|
  | **Default** | 64 | 32 | 16 |
  | **Large** | 96 | 48 | 24 |

  The set is independent of the display's scale (a scale of 2 asks for twice the pixels of whichever set). The cell grows with the icon (`UI_CELL_W`/`H` from the size), titles below; menu rows, the Details view's rows and the LaunchPad's buttons from the set's sizes. Sizes are a starting point, to be tuned later.
- **From the packages** (rules in wpsicon): Default 64 and 32 exact, 16 halved from 32; Large 96 exact, 48 halved and 24 quartered from 96. At a scale of 2: Default 128, 64, 32 exact; Large 192 from 256 (scaled down smoothly), 96 exact, 48 halved. The icon set can add its own 48, 24 and 16 (the small design) to its packages; an exact match is used first.
- **The open icon** (OS/2's animation icon; the owner's spec): a second icon shown while the object is open (a folder with a window, a program running). The theme gives special folders theirs (`NAME-open`: `folder-open`, `templates-open`, `home-open`, ...); an object can have its own: the Icon page's second field, **Open**. Objects with none show the normal icon with the in-use emphasis, as now.

## 4. OS/2's free icon layout

The owner's to-do (2026-11-22): OS/2's free (non-grid) layout spaced icons by their titles.

- **Folder's Icon view page: Layout:** grid (0.3's: fixed-width cells, rows as tall as their tallest title) or **free**.
- **Free:** each cell is as wide as its title needs, between the icon's width plus a margin and a maximum (**Proposed:** four icon widths, 256 px at the default 64), the title wrapped at that width; cells packed left to right to the window's width, each row as tall as its tallest; Arrange and Sort flow the same way. Locked icons stay; the others flow around them, as in the grid.
- `layout.c` gets per-item widths (it has per-item heights since 0.3); hit tests and drawing in the container use them.

## 5. Folder windows: place, size and view; the search field; column edges

- **Remember their place** (the owner's to-do): a folder window opens where it was closed, at its size, in its view, as OS/2's did. Kept with the folder (WPFolder state, per view: `win:icon`, `win:details`, `win:tree` = x, y, w, h). **WPS session:** the compositor places it (its `place` command, as for windows restored at login). **Inside GNOME** Wayland lets no program place its window: the size and view are kept, the position only when the extension places it (**Proposed:** the extension's `place` too).
- **Where the search field sits** (the owner's to-do): **System, Folders page:** top (0.3's), bottom, or floating (a small box at the window's lower right, as a type-ahead).
- **The resize pointer** on a details view's column edges (the owner's to-do): the pointer shape `col-resize` over an edge (the compositor's and GNOME's cursor themes have it).

## 6. The desktop's status line; positions from 0.2

- **The desktop has no status line** (open since 0.1): its messages ("Moved to the trash: 2 objects", errors) show for a few seconds in a small box at the bottom of the desktop's usable area, above the WarpCenter, as OS/2's desktop showed nothing but WPS's windows do; errors stay until clicked.
- **Positions from 0.2** (found in 0.3 step 6): icons placed for two-line titles can overlap whole titles. **Proposed:** the first time a folder with overlaps opens in 0.4, its status line offers **Arrange** (a link), and the offer is not repeated (the folder state `layout3`); nothing moves unasked.

## 7. Objects: Prevent delete, extension changes, shadows' menus

- **Prevent delete** (OS/2's no-delete style; the owner's to-do): a checkbox on the General page. Delete, Delete permanently, drops on the Trash Can and moves to the trash refuse such an object ("My System cannot be deleted: Prevent delete is on (its General page)"). **Proposed:** WPS's own objects (My System, My Storages, the Trash Can, Templates, Programs, System Setup and its objects) start with it on (a first-start step); renames and moves are not affected.
- **Confirm an extension change on rename** (the owner's to-do), when extensions are shown: "Change the extension from .odt to .txt? The file may open differently." **Use .txt** / **Keep .odt** / **Cancel**. Also when an extension is added or removed. Not asked for folders.
- **A shadow's menu is its original's** (found in 0.3 step 10), as on OS/2: wpsd builds the original's menu (Open With on a shadow of a file, its class's items), and the shadow's own items follow (Delete deletes the shadow; Properties shows the original's, as now).

## 8. Programs: executables' Program page; coming to the front

- **A Program page for executable files** (found in 0.3 step 7): a data file that is a program (ELF or a script with `#!`) gets the Program page of program objects: Working directory, Program type (automatic: 0.3's guess from the ELF file; window; text mode), Close window on exit. Kept in WPS's state.
- **Programs come to the front:** the window asks the compositor for an **xdg-activation token** with the click's serial and sends it with `open`; wpsd starts the program with `XDG_ACTIVATION_TOKEN` (and `DESKTOP_STARTUP_ID` for X11 programs). Inside GNOME this keeps new windows from opening behind.

## 9. The Colour Palette; the Background page's polish

- **The Colour Palette** (OS/2's; the owner's): a settings object in System Setup, opened as a window of colour samples (OS/2's had 30). Drag one (button 2) onto
  - a folder window's or the desktop's background: its background colour (Background page; the picture stays if it has one);
  - with **Ctrl**: its icons' title colour (a new field on the folder's Icon view page: **Title colour**);
  - a title bar: the active title bar's colour in the scheme (every window; the compositor's frames too);
  - a notebook's colour field: that field.
  **Edit colour...** (a sample's menu, or a double click): a colour editor (hue and saturation square, brightness, and `#rrggbb`).
- **The Background page's polish** (the owner's check of 0.3 step 3): the colour swatch shows the colour in use (OS/2's teal when none is set, marked "default"); the picture field shows a small preview beside its path.

## 10. Fonts in every WPS window

Found in 0.3 step 9: notebooks, dialogs, Find and the window list use the interface font.

- **System, Fonts page: Dialogs** (a new font): notebooks, dialogs, Find, the window list, the Font and Colour Palettes; a font dropped on one of those windows sets it (with Shift too).
- **Sizes follow GNOME's text scaling factor** (a font of 10 points is 10 points at the scale the user chose).
- **Edit font: a style list** (fontconfig's styles for the family: Regular, Light, Medium, Bold, Italic, ...), as OS/2's had; a font name says its style ("12.Noto Sans SemiBold").

## 11. Work Area folders

**Decided** (the owner's, 2026-11-21): in 0.4; the 0.3 design (section 12 of [v0.3-design.md](v0.3-design.md)) stands, detailed here.

- **Setting:** **Work area** checkbox on the folder's File page (OS/2's place for it).
- **The group:** objects opened from a work area folder (double-click, Open, from a shadow in it, or from a folder inside it) belong to it. wpsd records it when it starts them: it already knows which object each program was started from (the in-use emphasis) and its scope (`app-wps-*.scope`).
- **The windows:** the compositor links a scope's processes to their windows (Wayland: the client's PID through its socket's credentials; X11: `_NET_WM_PID`), and takes a group's minimize, restore and close.
- **The folder's window** opened: the group's windows restored (and objects that were open when it closed, opened again); minimized: they are minimized; closed: the programs asked to close (as at logout; a program that refuses keeps its window); restored: restored.
- **At logout** the group's open objects are kept; at login a work area folder that was open opens again with them (programs restart in the folder).
- **Inside GNOME:** the same through the extension (Mutter's windows have their PID); **Proposed** as the step's second part.

## 13. What 0.4 does not do

- File types from `user.mime_type` and the Type page: after 0.4 (**Decided**).
- Themes for other programs (GTK 3, Qt, cursors): 0.5. **Decided:** libadwaita programs keep their own look and title bars; the scheme's colours an option for them.
- More than one monitor, sharp X11 programs on scaled screens: 0.5.
- The Network object, undo for jobs, RDP: 0.6.
