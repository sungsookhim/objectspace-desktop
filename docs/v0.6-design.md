# Version 0.6: design (draft)

Draft, 2026-11-24, for the owner's choices. 0.6 gathers what the roadmap put after 0.5 ([roadmap.md](roadmap.md), "Proposed order", 0.6): TheBar's trays, more ways to see a folder, more than one screen, and the look of other programs. The choices marked **Decide** are the owner's; the rest is proposed and can change with them.

Nine parts, in three groups:

| Group | Parts | Size |
|---|---|---|
| **A. TheBar and folder windows** (the shell) | 1. TheBar's trays; 2. a menu bar in folder windows; 3. the Column view; 4. the Preview and Gallery views | M, M, M, L |
| **B. Screens and power** (the compositor) | 5. suspend after idle; 6. more than one screen; 7. sharp X11 programs on scaled screens | S, L, M |
| **C. Other programs' look** (themes) | 8. themes from the scheme objects (GTK 3, cursors, Qt); 9. libadwaita programs and the scheme's colours | L, S |

**Decide: one release or two.** All nine are more than any version so far. Proposed: **0.6 = groups A and B-5** (what the user sees in Objectspace's own windows, and suspend), **0.7 = B-6, B-7 and C** (screens and other programs' look), and the network and jobs (today's 0.7) move to 0.8, the helper programs to 0.9. Or all nine in 0.6, as the roadmap has it now.

## 1. TheBar's trays (OS/2 Warp 4's WarpCenter trays)

On OS/2 the WarpCenter held trays: named sets of objects (folders and programs) shown as small icons on the bar, one tray at a time, the tray button cycling through them.

- **A tray is a folder of shadows**, as the Launcher's buttons are: `~/.local/share/objectspace/Trays/<name>/`. So a tray is an object like any other: its notebook, its order (the folder's), shadows added and removed with the usual moves, and a **Trays** folder in System to see them all.
- **On the bar**, after the Window list button: the **tray button** (the current tray's name and a small arrow), then its objects as small icons. A click on the button: the next tray; on its arrow (or a right click): a menu of the trays (a check at the current), **Add tray**, **Rename tray...**, **Delete tray** (asks; its shadows go, never the objects).
- **The objects:** a click opens one (one click, as on the WarpCenter); a right click is its own menu, with **Remove from tray** added; dragging one off the bar onto the desktop or a folder moves its shadow; an object dropped on the bar's icons joins the current tray (a shadow is made), at the place it was dropped.
- **TheBar's notebook:** **Parts**, a **Trays** checkbox (on); the current tray kept in TheBar's settings, so it is the same after logging in again.
- **First start:** one tray, **Default**: shadows of My System, Programs, Objectspace Terminal and Find.

**Decide:** the first tray's name and objects (proposed above); whether the bar shows the tray's objects' titles (OS/2: icons only, titles in tooltips; proposed: as OS/2).

## 2. A menu bar in folder windows (Warp 4's folders had one)

- **Its menus:** **Folder** (Open as Icon, Tree, Details, Column, Gallery; Properties; Create another; Find...; Close), **Edit** (Select all, Deselect all, Copy, Move, Create shadow, Delete, Rename; Undo of the last arrange), **View** (the views; Sort by; Arrange; Refresh; Show hidden files; Icon size), **Selected** (the selected objects' own menu, as their pop-up menu, greyed when nothing is selected), **Help** (the folder's keys, About Objectspace).
- **On or off:** a **Menu bar** checkbox on the folder's View page, for one folder or, through **Class...**, all folders. Off by default (as now: the pop-up menus remain the way, as on OS/2).
- **Off, but wanted for a moment:** **Alt** pressed and released alone shows it with its first menu ready for the keyboard (arrows, Enter, Esc), as other systems do; Alt held while clicking shows it while held; **F10** too. It goes again when a menu is closed.
- The desktop has none (OS/2's desktop had none either).

**Decide:** off or on by default for new folders; the menus' names (OS/2 Warp 4 used Folder, Edit, View, Selected, Help; proposed as Warp 4).

## 3. The Column view (NeXTSTEP's browser)

- **A fourth view** beside Icon, Tree and Details: the folder's contents as a column of small icons and titles; a folder chosen in a column opens its contents in the next column to the right; the window scrolls sideways as columns are added; a path above the columns, each part a button back to that column.
- **Keys:** up and down in a column, right into the chosen folder's column, left back; Enter opens the object; typing jumps to a name in the column with the focus (as type-ahead does now).
- **A file chosen:** the last column shows it large with its title, size, type and date (NeXT showed nothing; Mac OS X's column view showed this).
- Each column is a folder window's list, so drag and drop, menus, selections and live changes are the ones folders have.

## 4. The Preview and Gallery views

- **Thumbnails:** pictures (and with installed thumbnailers, documents and videos) shown by what they look like, made off the interface's thread by `glycin-thumbnailer` (as backgrounds are now) and the system's other thumbnailers (`/usr/share/thumbnailers`), and **kept in the shared cache** (`~/.cache/thumbnails`, the freedesktop.org standard), so Objectspace and other file managers make each one once.
- **The Preview view:** the Icon view with thumbnails in place of the type's icon (a folder setting, **Show pictures**, on the View page, off by default; the Icon size chooses their size).
- **The Gallery view:** one object shown big, the folder's others in a strip of thumbnails beneath; left and right move through them; Enter opens it; the big one's title, size and date beside it.

**Decide:** whether thumbnails go in the shared cache (proposed) or Objectspace's own; whether **Show pictures** is a separate Preview view (a view of its own on the menu) or a setting of the Icon view (proposed: a setting).

## 5. Suspend after idle

- After GNOME's **Automatic Suspend** time without input (its settings, read as the idle delay is now: on battery and plugged in, separately), the machine sleeps, through logind; the screen is locked first, as now. Programs that hold the screen on (idle-inhibit) and logind's inhibitors hold it off too.
- In the Objectspace session only (inside GNOME, GNOME does it).

## 6. More than one screen

- **The desktop:** **Decide.** (a) one desktop across all screens (icons anywhere, as one big area; OS/2 had one screen); or (b) the desktop on the main screen and its background alone on the others (proposed: (a), which most systems do and which keeps one desktop folder).
- **TheBar:** on the main screen, chosen in its notebook (**Screen**); the usable area of the other screens is all of them.
- **Windows:** opened on the screen with the pointer; maximized on their own screen; moved between screens by dragging, and with Super+Shift+Left and Right; restored at login on the screen they were on, or the main one if it is gone.
- **Screens added and removed** while running: windows on a removed screen move to the main one.
- Arrangement and scale of the screens: GNOME's (Settings, Displays, `monitors.xml`), as the scale already is.

## 7. Sharp X11 programs on scaled screens

- Today XWayland programs on a screen scaled to 2 are drawn at 1 and stretched: blurry. With XWayland's own scaling (`-hidpi`, or the compositor telling X11 programs the scale through `Xft.dpi` and `GDK_SCALE`, as GNOME's experimental setting does), they draw at the screen's scale.
- A System setting (**Scale X11 programs themselves**, on), since some old programs then look small.

## 8. Themes from the scheme objects

Objectspace's schemes (Classic, Dark, High contrast, and the user's own) set the colours and fonts of Objectspace's windows. Here they reach other programs too, in the Objectspace session (inside GNOME, GNOME's theme stays):

- **GTK 3:** a theme made from the scheme (`~/.local/share/themes/Objectspace-<scheme>/gtk-3.0/gtk.css`: the window, button, selection and text colours, the fonts), set for the session (`gtk-theme-name` in the session's GTK settings, not GNOME's), made again when the scheme changes.
- **Cursors:** an Objectspace cursor theme (OS/2's arrow, busy clock and hand redrawn, in the icon set's style), made by `tools/icons` and installed with the RPM.
- **Qt:** the scheme's colours as a Qt palette (through `qt6ct`/`qt5ct`, when installed).
- **Icons for other programs:** Objectspace's isometric icons exported as a freedesktop.org icon theme (folders and file types), so file dialogs show the same pictures.

**Decide:** which of the four (proposed: GTK 3 and cursors first; Qt and the icon theme after).

## 9. libadwaita programs

GNOME's own programs (libadwaita, GTK 4) keep their look and their own title bars (the owner's, roadmap). The **Scheme Palette** gets an option, **Offer the scheme's colours to GNOME programs** (off by default): the scheme's selection colour as their accent colour (GNOME's `accent-color`), and Dark as their dark style.

## Tests

Each part a headless test where it can be: the trays and the menu bar in `tests/comp/` (clicks and pictures), the views in GUI self-tests (`gui/shell/selftest.c`, golden), thumbnails with a fake thumbnailer, suspend with a fake logind, more than one screen with the headless backend's several outputs, the themes by the files they write.
