# Version 0.4 implementation plan

Draft, 2026-11-22, for [v0.4-design.md](v0.4-design.md).

**How to read it:**

- Steps in order; each ends usable, tested and pushed, and the owner tries it on the VM where marked **(VM)**, from the RPM or with `git pull && make session`.
- Sizes are relative (S, M, L), as in the roadmap.
- Grouped so that each step works in one part of the code: icons (2, 3), folder windows (4, 5), objects (6), palettes (7, 8), work areas (9, 10).

## Step 1. Groundwork (S)

1. `VERSION` 0.4.0-dev.
2. **librsvg** as a build and run dependency (the spec's `BuildRequires`, the Makefile's `pkg-config`); the RPM's new requirements (Pillow, zlib, librsvg) built in mock.
3. **Carried fixes** (design 12): Open With's list on a worker; a left-side drawer's cascade opening to the left; M4 scenario 38 and the two-window drag self-test rerun, fixed or explained.

**Checks:** `make test` and the GUI tests; a mock build; the drawer cascade headless.

## Step 2. Icon themes (M–L) (VM)

1. **wpsicon in the window:** `icons.c` loads packages (and plain pictures) through `wpsicon.c`, renders the size asked (device pixels) with a cache by (package, size); the SVG through librsvg.
2. **Themes:** the installed and the user's themes listed; **System, Icons page: Icon theme** (default WPS (flat)); a change redraws every window, the LaunchPad, the WarpCenter, menus.
3. **Names:** wpsd's listings say `theme:NAME` for WPS's own objects and data files by type (design 2); the window resolves them (theme, then wps-flat, then the drawn kind). The system buttons (WarpCenter, LaunchPad) from the theme.
4. **Choose...** on the Icon page takes `.wpsicon` packages, and unpacks `.ico` and `.icns` into packages.

**Checks:** unit tests for the type-to-name table and the theme lookup (a missing name falling back); headless: the desktop drawn with each theme; a theme switched live.

## Step 3. Icon sizes and the open icon (M) (VM)

1. **System, Icons page: Icon size** (32, 48, 64, 96, default 64; design 3): cells, layout and hit tests from the size; the desktop and every folder follow live.
2. **The open icon:** the theme's `NAME-open` for special folders, the Icon page's **Open** field for an object's own; shown while open (a folder with a window, a program running: the in-use state wpsd sends).
3. Menus and the LaunchPad at their sizes (16, 32) and scales through the rules.

**Checks:** headless: icons at each size (no overlaps, sharp at each; 48 from 96); a folder's icon changing to its open one while its window is open.

## Step 4. OS/2's free icon layout (M) (VM)

1. `layout.c`: per-item widths beside 0.3's heights; free packing (rows to the window's width, as tall as their tallest); Arrange and Sort in it; locked icons kept.
2. The container: hit tests, drawing and title wrapping at each item's width.
3. **Folder's Icon view page: Layout** grid or free.

**Checks:** unit tests (`test_layout`: widths, packing, locked icons); headless: a folder of long and short titles in free layout.

## Step 5. Folder windows and the desktop's messages (M) (VM)

1. **Folder windows remember** their place, size and view (WPFolder `win:VIEW`); the WPS session places them through the compositor; inside GNOME size and view (the extension's `place`, if it can).
2. **The search field's place:** top, bottom, floating (System, Folders page).
3. **The resize pointer** on column edges.
4. **The desktop's status line:** a transient box above the WarpCenter.
5. **Positions from 0.2:** the status line's Arrange offer, once.

**Checks:** headless (WPS session): a folder closed and opened again at the same place and size; the search field at the bottom; a message shown on the desktop; the cursor shape over a column edge.

## Step 6. Objects and programs (M) (VM)

1. **Prevent delete:** the General page's checkbox (WPObject state `nodelete`); wpsd refuses delete, trash and Trash Can drops; WPS's own objects get it at the first start (a new first-start step).
2. **Extension change on rename:** the dialog (Use / Keep / Cancel) when extensions are shown.
3. **A shadow's menu is its original's:** wpsd's `menu` for a shadow builds the target's, then the shadow's items.
4. **Executables' Program page** (design 8); wpsd's `open` follows it for program files.
5. **Activation tokens:** the window asks for one (`xdg_activation_v1`) and sends it with `open`; wpsd sets `XDG_ACTIVATION_TOKEN` and `DESKTOP_STARTUP_ID`.

**Checks:** wpsd tests (delete refused; the shadow's menu; an executable opened by its page's settings; the token in the program's environment); headless: the rename dialog.

## Step 7. The Colour Palette (M) (VM)

1. **WPColorPalette** in System Setup (a first-start step adds it, as the Font Palette in 0.3); its window of samples; **Edit colour...** (hue/saturation, brightness, hex).
2. **Drops:** a folder's or the desktop's background; with Ctrl, its title colour (Icon view page: **Title colour**); a title bar: the scheme's active title colour (the compositor's frames too); a notebook's colour field.
3. **The Background page's polish:** the swatch shows the colour in use; a picture preview.

**Checks:** a self-test dropping a colour on a folder, with Ctrl, on a title bar and on a notebook field; headless screenshots of the Background page.

## Step 8. Fonts in every window (S–M) (VM)

1. **System, Fonts: Dialogs** for notebooks, dialogs, Find, the window list and the palettes; drops on those windows.
2. **Text scaling:** font sizes times GNOME's text scaling factor.
3. **Edit font: a style list** from fontconfig; font names with any style.

**Checks:** the `fonts` self-test extended (a notebook's font; a style); a unit test for font names with styles.

## Step 9. Work Area folders, part 1: the group (M–L) (VM)

1. **The setting:** Work area on the folder's File page.
2. **wpsd:** objects opened from a work area (or from a folder or shadow in it) recorded as its group, with their scopes; the group's state kept at logout.
3. **The compositor:** a scope's processes linked to their windows (Wayland client PID; X11 `_NET_WM_PID`); a group's minimize, restore, close.
4. **The folder's window:** minimizing, restoring and closing it act on the group (WPS session).

**Checks:** headless (WPS session): two test programs opened from a work area folder, minimized and restored with it, closed with it.

## Step 10. Work Area folders, part 2: login and GNOME (M) (VM)

1. **At login:** a work area that was open opens again with its objects (programs restarted in the folder).
2. **Inside GNOME:** the extension acts on the group's windows through Mutter (PIDs).

**Checks:** headless: a work area reopened after a restart of the session with its programs; the extension's part in the GNOME probe tests.

## Step 11. The release (S)

`VERSION` 0.4.0, the RPMs built in mock, `rpmlint`, a fresh-VM install and an upgrade from 0.3.0 (the owner's), the roadmap and README, release notes, the GitHub release made as a draft for the owner's check, then published (tag `v0.4`).

## Order and checkpoints

- Steps 2 and 3 first: every later screenshot and test sees the new icons and sizes.
- Steps 4 and 5 change the folder window; step 6 the objects; 7 and 8 the palettes; 9 and 10 need the compositor and the extension.
- The owner checks on the VM after each step marked **(VM)**.

## Risks

- **Icon size** touches every place a 32 px icon is assumed (cells, menus, the LaunchPad, drag images): step 3 gathers them.
- **librsvg** in the window process: SVGs are drawn on the UI thread when first needed; a large or broken SVG must not stall it (a size limit; drawn once per size and cached).
- **Work areas** depend on linking processes to windows: programs that hand their window to an instance already running (most GNOME apps, Firefox) belong to the first instance's group only. The design accepts that; the status line says so when it happens.
- **Window placement inside GNOME** depends on the extension.
